# Экзамен МДК 02.01 - Вариант 1

## Описание
Для сдачи экзамена необходимо настроить сеть из трех машин: ISP (маршрутизатор), Server (сервер) и cli (клиент). Все машины должны работать корректно вместе.

## Схема сети
- ISP: сервер маршрутизации и DHCP
- Server: файловый сервер с RAID, Samba DC, NFS
- cli: клиентская машина для доступа к сервисам
- Все машины подключены в локальную сеть

## Задание

### I. Настройка сетевого взаимодействия (на сервере ISP)
**Цель:** Настроить базовое сетевое взаимодействие и DHCP для внутренней сети.

**A. Настройка внутреннего IP адреса**  
Назначьте интерфейсу внутренней сети первый доступный IP адрес из подсети 10.0.128.0/24 (т.е. 10.0.128.1).  

### Для isp:
**Команды:**
```bash
hostnamectl set-hostname isp.ilove.sa
exec bash
```
```bash
cd /etc/net/ifaces/
mkdir -p ens19
cd ens19
echo 10.0.128.1/24 > ipv4address
echo BOOTPROTO=static > options
echo TYPE=eth >> options
apt-get update && apt-get install -y iptables nano
```
*В файле:*
```bash
nano /etc/net/sysctl.conf
```
*Записать:*
```bash
net.ipv4.ip_forward = 1
```

**B. Настройка iptables для выхода в интернет**  
Установите iptables и настройте правила для NAT (маскарадинга) на внешнем интерфейсе, чтобы машины внутренней сети могли выходить в интернет.  

**Команды:**
```bash
sysctl -p
iptables -t nat -A POSTROUTING -o ens18 -j MASQUERADE
iptables-save -f /etc/sysconfig/iptables 
systemctl enable --now iptables
systemctl restart network
```

**C. Настройка DHCP сервера**  
Установите и настройте DHCP сервер для автоматического назначения IP адресов.  

*1. Статический адрес для Server:* Второй свободный адрес подсети (10.0.128.2)  

*2. Динамический пул:* Адреса с 10.0.128.50 по 10.0.128.100  

### Для isp:
**Команды:**
```bash
apt-get install -y dhcp-server
cd /etc/dhcp/
```

*В файле:*
```bash
nano /etc/sysconfig/dhcpd
```

*Записать:*
```bash
DHCPDARGS=ens19
```

*В файле:*
```bash
nano dhcpd.conf
```
*Записать:*
```bash
ddns-update-style none;
subnet 10.0.128.0 netmask 255.255.255.0 {
  option routers         10.0.128.1;
  option subnet-mask     255.255.255.0;
  option domain-name "ilove.sa";
  option domain-search "ilove.sa";
  option domain-name-servers     10.0.128.2, 8.8.8.8, 8.8.4.4;
  range 10.0.128.50 10.0.128.100;
  max-lease-time 43200;
  default-lease-time 21600;
}
host srv {
hardware ethernet свой-MAC-адрес;
fixed-address 10.0.128.2;
}
```

MAC-адрес отображается жёлтым, команда на srv: 
```bash
ip -c a
```

**Команды:**
```bash
dhcpd -t
systemctl restart dhcpd
systemctl enable --now dhcpd
systemctl restart network
```

### Для cli:

### II. Настройка сетевого каталога (на сервере Server)
**Цель:** Создать отказоустойчивый RAID массив и опубликовать его по сети.

**A. Создание RAID-5**  
На дисках sdb, sdc, sdd создайте RAID-5 массив.  
### Для server:
**Команды:**
```bash
mdadm --create --verbose /dev/md0 --level=5 --raid-devices=3 /dev/vdb /dev/vdc /dev/vdd
mdadm --detail --scan >> /etc/mdadm.conf
mdadm --assemble --scan 
```

**B. Монтирование массива**  
Смонтируйте RAID в каталог /mnt/raid_1  

```bash
mkfs.ext4 /dev/md0
mkdir -p /mnt/raid_1
chmod 777 /mnt/raid_1
mount /dev/md0 /mnt/raid_1
UUID=$(blkid -s UUID -o value /dev/md0) && echo "UUID=$UUID /mnt/raid_1 ext4 defaults 0 0" >> /etc/fstab
apt-get -y install nfs-server
systemctl enable --now nfs
```

**C. Публикация через NFS**  
Опубликуйте /mnt/raid_1 как общедоступный NFS каталог.  

*В файле:*
```bash
nano /etc/exports
```
*Записать:*
```bash
/mnt/raid_1 10.0.128.0/24(rw,no_subtree_check,insecure)
```

**Команды:**
```bash
systemctl restart nfs
```

**D. Монтирование на клиенте cli**  
На машине cli примонтируйте сетевой каталог в /share_1  

### Для cli:
**Команды:**
```bash
apt-get -y install nfs-clients
mkdir /share_1
mount 10.0.128.2:/mnt/raid_1 /share_1
```

*В файле:*
```bash
nano /etc/fstab
```
*Записать:*
```bash
10.0.128.2:/mnt/raid_1 /share_1 nfs rw 0 0 
```

### III. Настройка удаленного доступа
**Цель:** Настроить SSH доступ между машинами без пароля.
**A. SSH доступ cli ко всем машинам**  
Настройте возможность подключения с cli на ISP и Server по SSH.  
**B. Псевдонимы для подключения**  
Настройте алиасы: `ssh ISP` и `ssh Server`  
**C. Без пароля**  
Используйте ключи SSH для аутентификации.  
**D. Нестандартные порты**  
Используйте порт 2222 для SSH подключений.  
**E. Пользователь sshuser**  
Создайте пользователя sshuser на всех машинах.  

### Для cli, server и isp:
**Команды:**
```bash
apt-get install -y openssh
```
*В файле:*
```bash
nano /etc/openssh/sshd_config
```
*Записать:*
```bash
Port 2222
PasswordAuthentication yes
PubkeyAuthentication yes
MaxAuthTries 5
AllowUsers user
```
**Команды:**
```bash
systemctl enable --now sshd
systemctl restart sshd
```

### Для isp:
**Команды:**
```bash
useradd -m -s /bin/bash user
passwd user #пишешь пароль resu
```

### Для cli:
**Команды:**
```bash
ssh-keygen #после команды тупо жмёшь Enter на все вопросы
```
```bash
ssh-copy-id -p 2222 user@10.0.128.1
```
```bash
ssh-copy-id -p 2222 user@10.0.128.2
```

*В файле:*
```bash
nano ~/.ssh/config
```
*Записать:*
```bash
Host ISP
    HostName 10.0.128.1
    Port 2222
    User user
    IdentityFile ~/.ssh/id_rsa

Host Server
    HostName 10.0.128.2
    Port 2222
    User user
    IdentityFile ~/.ssh/id_rsa
```

### Для cli, server и isp:
**Команды:**
```bash
useradd -m -s /bin/bash sshuser
usermod -aG wheel sshuser
passwd sshuser # Пароль P@ssw0rd
```

### IV. Управление пользователем sshuser
**Цель:** Настроить ограниченные sudo права для sshuser.
**A. Ограниченные права**  
sshuser может выполнять только shutdown, reboot и htop через sudo.  
**B. Без пароля для sudo**  
Настроить NOPASSWD для разрешенных команд.  

### Для cli, server и isp:

**Команды:**
```bash
apt-get -y install sudo htop
chmod 4755 /usr/bin/sudo
which shutdown reboot htop 
```

Проверь путь для всех команд, на каждой машине, могут отличаться, у меня было так:

Для cli:
```bash
/sbin/shutdown, /sbin/reboot, /usr/bin/htop
```

Для isp:
```bash
/usr/sbin/shutdown, /usr/sbin/reboot, /usr/bin/htop
```

Для server:
```bash
/sbin/shutdown, /sbin/reboot, /usr/bin/htop
```

### Для cli, server и isp:

*В файле:*
```bash
EDITOR=nano visudo
```
*Записать:*
```bash
sshuser ALL=(root:ALL) NOPASSWD: /sbin/shutdown, /sbin/reboot, /usr/bin/htop
# Копируй пути выше, если они у тебя те же на тех же машинах, что и у меня
```

**Команды:**
```bash
reboot # Не должна проходить
sudo reboot # Проходит
```

### VI. Настройка iptables (на ISP)
**Цель:** Настроить фильтрацию трафика.

**A. Запрет транзитного трафика**  
Запретить весь транзитный трафик, кроме:  
- Established и related соединения  
- Порты 80, 443, 53  

**Команды:**
```bash
iptables -F
iptables -t nat -F
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT
iptables -A INPUT -i lo -j ACCEPT
iptables -A FORWARD -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A FORWARD -p tcp --dport 80 -j ACCEPT
iptables -A FORWARD -p tcp --dport 443 -j ACCEPT
iptables -A FORWARD -p tcp --dport 53 -j ACCEPT
iptables -A FORWARD -p udp --dport 53 -j ACCEPT
iptables -t nat -A POSTROUTING -o ens18 -j MASQUERADE
iptables-save > /etc/sysconfig/iptables
```

### V. Настройка службы каталогов Samba DC (на Server)
**Цель:** Создать домен и пользователей для аутентификации.

**A. Домен ilove.sa**  
Настройте Samba как контроллер домена с именем ilove.sa.  

**B. Пользователи и группа**  
Создайте пользователей variant1_1, variant1_2, variant1_3 и группу variant1_group.  

**C. Аутентификация на cli**  
Пользователи домена должны иметь возможность входа на cli.  

**D. Sudo права для группы**  
Пользователи variant1_group имеют те же ограниченные права на cli, что и sshuser.  

### Для server:
**Команды:**
```bash
apt-get install -y samba krb5-workstation task-samba-dc bind-utils
systemctl disable --now smb nmb winbind
rm -f /etc/samba/smb.conf
rm -rf /var/lib/samba/*
rm -rf /var/cache/samba/*
samba-tool domain provision
```
(Везде жмёшь enter, кроме пункта DNS forwarder IP address - здесь пиши "8.8.8.8", а далее вводишь пароль "P@ssw0rd")
```bash
cp /var/lib/samba/private/krb5.conf /etc/krb5.conf
```
```bash
systemctl enable --now samba
```
```bash
samba-tool user create variant1_1 'P@ssw0rd'
samba-tool user create variant1_2 'P@ssw0rd'
samba-tool user create variant1_3 'P@ssw0rd'
samba-tool group create "variant1_group"
samba-tool group addmembers "variant1_group" variant1_1,variant1_2,variant1_3
samba-tool user enable variant1_1
samba-tool user enable variant1_2
samba-tool user enable variant1_3
```

### Для cli:
**Команды:**
```bash
apt-get -y remove alterator-datetime
apt-get -y install task-auth-ad-sssd bind-utils alterator-auth
```
Далее заходишь в cli с графической оболочкой, открываешь system management center -> authentication -> выбираешь Active Directory or ALT Domain, домен уже будет указан верный -> Apply
```bash
kinit Administrator@ILOVE.SA
kinit variant1_1@ILOVE.SA
kinit variant1_2@ILOVE.SA
kinit variant1_3@ILOVE.SA
```

*В файле:*
```bash
EDITOR=nano visudo
```
*Записать:*
```bash
%variant1_group ALL=(ALL) NOPASSWD: /sbin/shutdown, /sbin/reboot, /usr/bin/htop
```
